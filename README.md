# dobladillo

A scriptable toolchain for DNA origami **bricks**: reusable parts with typed
interfaces, composed into larger assemblies and simple stochastic mechanisms,
with predicted properties, everything the lab needs to build them, and an
image-ingest path that closes the loop between prediction and experiment.

The gap it fills: existing tools design single structures (caDNAno, scadnano,
ATHENA) or simulate them (oxDNA, CanDo). None offers a parts library with
characterised, composable interfaces and measured assembly yields.

Design document: `docs/DESIGN.pdf`. Roadmap status: `docs/STATUS.md`.
Working rules for coding agents: `AGENTS.md`.

## Install

```bash
uv sync --extra dev --extra design
```

## Use

```bash
uv run dobladillo analyse                    # turn a finished run into observables with experimental counterparts
uv run dobladillo build bundle               # a six-helix bundle on the honeycomb lattice
uv run dobladillo build pair                 # both arms of the twist pair, written side by side
uv run dobladillo build rectangle            # a rothemund-style rectangle on the square lattice
uv run dobladillo geometry                   # show the geometry constants, and where this project disagrees
uv run dobladillo lab order                  # plates, pooling map and cost for ordering a part's staples
uv run dobladillo lab protocol               # the folding protocol sheet, with the magnesium screen laid out
uv run dobladillo lint                       # check a design against the rules. exits non-zero on a hard violation
uv run dobladillo rules                      # list the design rules, and what is knowingly not checked
uv run dobladillo scaffolds                  # list the scaffold strands available, asked of scadnano directly
uv run dobladillo sim bundle                 # write a self-contained oxdna job bundle. runs nothing
uv run dobladillo sim check                  # is this run something whose numbers mean anything? exits non-zero if not
uv run dobladillo twist-pair                 # the matched pair that tests whether the twist correction does anything
```

### For agents

Every command takes `--json`, and with it stdout carries exactly one JSON
object: no banners, no colour, no progress. Failures are JSON too, with a
stable `error.kind`, and exit non-zero, so a caller never has to tell a
traceback from a result. Warnings go to stderr.

Start with `dobladillo describe --json`, which emits the whole command surface
-- commands, options, types, defaults -- generated by walking the app, so it
cannot fall out of date with what the tool actually accepts.

```bash
uv run dobladillo describe --json
uv run dobladillo build bundle --json | jq .scaffold
```

There is also a skill file, generated from the command surface so it cannot
drift from what the tool accepts:

```bash
uv run dobladillo skill > ~/.claude/skills/dobladillo/SKILL.md
```

## Principles

- **Wrap, don't rewrite.** scadnano is the design data model, oxDNA the
  physics, NUPACK/ViennaRNA the thermodynamics.
- **Everything is code.** A design is a Python script producing a
  deterministic artefact. No hand-edited design files in the repo.
- **Every prediction carries a comparison hook.** Any simulated observable
  must have a defined experimental counterpart.
- **Reproduce before inventing.** Each tier starts by reproducing a published
  result.
- **Human gates are explicit.** The toolchain never assumes a simulation was
  run or a structure folded; it consumes result files placed in `data/`.
